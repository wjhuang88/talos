## Proposed lease contract for B/C review

Placement: provider-layer shared CredentialResolver owned by an explicitly constructed host/provider-factory lifecycle context (in talos-provider, not ConfigStore, TLOG, agent turn, global singleton, nor a per-request HTTP adapter). One Arc resolver per admitted lifecycle context; providers sharing that context share the flight table. Independent runtime/SDK hosts do not implicitly share accounts or secrets. Do not change public RuntimeBuilder defaults or ARCH-035 host composition; source compatibility for injection remains. Concrete type names are descriptive proposals, not public API promises.

Lease key K = (stable enrolled profile identity, opaque account/tenant identity, typed exact audience/approved destination identity, credential-source/enrollment identity, config generation). Keys contain no secret or raw bearer. Acquisition issuer/exchange and inference audiences are different; no model alias or untrusted URL alone grants authority. Same names with different accounts, resources, issuers, audiences or contexts must not share a flight or lease. Configuration generation G is a never-reused monotonic epoch of the enrolled profile/context, advanced on logout, enrollment/config replacement and shutdown; atomic with revocation. Same G may install multiple leases with strictly distinct opaque revisions R; neither equal bytes nor refresh within one generation implies equal revision. Counters must not wrap/reuse (fail closed); a newly constructed resolver has a fresh identity.

### Explicit source admission (ADR-108)

Before cache lookup, flight admission, secret-store access, acquisition or any outbound request, validate the effective explicit source selection for the binding. Reject multiple competing explicit credential sources (including a dynamic source plus an explicitly selected incompatible static source, or two distinct dynamic sources) and inconsistent source/enrollment bindings with a redacted typed configuration error. Do not choose by order, silently fall back, probe a source, invoke a helper, or send a request. Count source selectors, not the fields needed by one source; ambient environment availability alone is not an explicit competing selector. Auth omitted retains the existing static resolution and inline/stored/environment precedence below; multiple legacy key inputs are not a dynamic-source conflict. This is a conceptual admission rule, not a new schema or authorization grant. C consumes only admitted bindings and must not dispatch on rejection.

C receives opaque LeaseRef carrying K/G/R and usable-until metadata; no serializable token, raw credential-bearing Debug or public unrestricted getter. Minimal conceptual operations:
1. acquire(binding, caller deadline/cancellation) -> lease reference or redacted typed error (cached or one shared acquisition).
2. with_current_credential(lease reference, binding, synchronous scoped consumer) -> bounded credential access for C's authorizer, after key/generation/revision/expiry validation; no secret retained in handle.
3. invalidate_if_current(binding, G, R) -> Invalidated / Stale / Revoked (atomic compare-and-swap; a stale 401 never removes a newer lease).
4. validate/admit_current(binding, G, R, deadline) -> live admission guard/decision at final dispatch boundary. B supplies the lifecycle check and linearization primitive; C integrates with sealed request transport. Do not hold a resolver lock across network await. Revocation wins before dispatch admission; already admitted/in-flight transport is C's cancellation responsibility, not retroactive recall of bytes.
5. revoke_profile / replace_config / shutdown -> advance epoch, detach/cancel producer, retire entry and reject late publish. Acquisition adapter receives a cancellation/deadline and returns typed bounded material with expiry, not final HTTP headers.

C owns exact destination checks and enrollment policy, final sealed request header/signature construction, pre-dispatch revalidation, retry eligibility, stream commit, reproducible body and joint attempt budget; B never sends or replays requests. C must discard stale authorized request and obtain fresh authorization only when policy/budget permits. D Copilot login/exchange/headers, E AWS credential chain and exact request SigV4, F Vertex ADC acquisition/migration, G authorized bounded helper execution remain distinct. B provides no vendor OAuth flow, arbitrary shell, signing, transport replay, new credential-store dependency, or provider enablement.

## Concurrency, revocation and limits (candidate for activation review)

One resolver-owned flight per K, not owned by the first waiting request. Publish only if K, G and unique flight identity still match under the registry gate; installation assigns a fresh R. A waiter uses its own deadline/cancellation and detaches without aborting a producer while other waiters remain. Last waiter departure cancels and retires that flight identity atomically; a new waiter can start a fresh flight, never join cancelled state. Flight identity retirement and actual producer termination are distinct. Reserve a resolver-wide producer permit before spawning; retain it through cancellation, deadline expiry, logout, replacement and retirement until the actual task exits (including acquisition cleanup). Track retiring tasks independently of the current flight table; a replacement flight may start only with a free permit. At saturation reject admission with a redacted capacity error, never release a permit merely because a waiter detached or a flight was removed. Release exactly once on confirmed termination, including error/panic/abort cleanup; failed spawn releases its reservation without starting work. Producer has its own bounded deadline and cancellation, no orphan background tasks. No lock held across acquisition await. Errors are redacted and shared for that flight, not endlessly retried; subsequent call explicitly starts a new flight under bounds. Shutdown closes admission, advances generations, cancels and joins producers within a bounded shutdown deadline; late completion rejected even if cancellation is ignored. If the shutdown deadline expires before actual exit, report a redacted shutdown failure, keep admission closed and retain permits/task tracking until termination; do not report a successful join or recycle capacity. Logout or replacement invalidates every affected key/flight; no old-generation fallback. A revoked/expired/evicted handle is never resurrected; do not recycle revision identities. Keep current leases only while valid, retire expired/invalid atomically, fail closed on capacity rather than evicting a live/in-flight entry and losing revocation state.

| Candidate boundary | Value and rationale |
|---|---|
| Per resolver cache slots | 64 distinct K slots including cached and in-flight keys; explicit cap, sufficient initial margin over typical configured provider/account count (engineering proposal, no measured population). Expired idle slots may be reclaimed; reject new distinct keys at saturation with redacted capacity error. |
| Credential payload | 16 KiB maximum per dynamic access-lease material; 64 × 16 KiB = 1 MiB resident cached payload ceiling (metadata, bounded temporary producer buffers and C request copies excluded). Bound producer result before allocation/acceptance; no generic unbounded credential object. |
| Concurrency | At most 16 reserved or actually running producers per resolver (including retired/cancellation-delayed tasks until confirmed exit), 64 attached waiters per key and 256 across resolver; fail bounded admission. Proposed producer deadline max 30 s, caller wait no longer than its own deadline, no implicit retry. Tune only through reviewed evidence; D–G may require separately accepted acquisition constraints. |
| Dynamic lease lifetime | Maximum 86400 s from acquisition start; existing Vertex caps reported lifetime at 86400. Clamp shared cache lifetime, never increase issuer expiry; missing/invalid/nonpositive expiry rejected for dynamic lease. Static legacy supplied keys are a separate no-expiry path; do not artificially expire them. |
| Refresh/dispatch safety margin | min(60 s, max(1 s, 10% of bounded span)); refuse if span <= 1 s or remaining usable time <= 0. 60 s aligns existing Vertex early refresh for normal lifetimes; adaptive smaller margins avoid wasting all short leases while preserving minimum. Existing Vertex one-second behavior stays unchanged pending F migration review. |

Expiry model: sample monotonic m0 and wall w0 at acquisition start. span = min(86400 s, absolute expiry minus w0 if supplied, relative TTL if supplied); at least one issuer expiry required. Use checked arithmetic, reject invalid clock/overflow; margin as above, usable = span − margin. Dm = m0 + usable, Dw = w0 + usable. At publish, acquisition reuse and dispatch admission require m < Dm AND w < Dw; once invalidated retire permanently. This conservatively also checks derived wall limit for relative TTL, catching forward wall jumps/suspend even if monotonic clock stalls. Forward jump can expire early, never extend. Backward jump cannot extend original Dm, and a retired lease cannot return even if wall time recovers. No guarantee of accurate issuer time if wall was already wrong at acquisition or both clocks unreliable; require redacted failure on invalid clock, cap exposure and leave vendor clock trust/signing/skew to E/F. No implicit wall-clock deadline recomputation from later samples. Treat exact boundary as expired.

## Storage, diagnostics and implementation boundaries

Access tokens reside only in bounded resolver process memory; opaque metadata-only handles never serialize to TOML, credentials.toml, history, debug, telemetry, crash reports or UI. Avoid copies; bounded temporary buffers and redacted typed errors; no secret-bearing cache keys, logs, URLs, or error chain. Static legacy file persistence remains unchanged under ADR-023, not a dynamic storage precedent. Persistent dynamic refresh material requires explicit enrollment and an approved OS store. B defines an injectable availability/storage boundary and fake locked/unavailable tests, not new OS native dependency or vendor enrollment. Missing/locked/denied store: fail requested persistent enrollment with actionable redacted error, no fallback file or silent downgrade; headless may use explicitly supplied supported credential without persistent enrollment, otherwise fail closed, no UI or helper launch. Any actual new OS secret-store implementation is separate scope per parent/ADR and requires review. Do not guarantee physical memory erasure, swap prevention or process-global memory bound across independently created resolvers.
