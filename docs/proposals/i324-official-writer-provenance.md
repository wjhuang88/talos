# I324 / #919 — official writer provenance: D1 security/API review candidate

**Proposed / NOT accepted; test-only evidence acquisition.** Main contains #931 (non-binding proposal) and #928 (test-only parser/query evidence). No production wiring or permission change.

The selected writer can be a Scoop shim, package cmd launcher or actual native Git image. Git 2.36.1 lacks five var queries and committed-tree check-attr. Version/path guesses are not a trust basis. The [upstream release](https://github.com/git-for-windows/git/releases/tag/v2.36.1.windows.1) publishes SHA-256 receipts for MinGit and PortableGit. The new hosted Windows oracle verifies both archives before extracting (PortableGit extracted as data), records exact relative image hashes, and uses distinct markers only inside disposable packages to observe system config and attributes roots, missing/empty states and XDG/HOME precedence. No caller installation or PATH is changed, and no absolute source paths or configuration contents are printed. The output is empirical fixture evidence, not permission or an attested installation profile.

Release-matched upstream implementation: [attr.c](https://github.com/git-for-windows/git/blob/v2.36.1.windows.1/attr.c#L837-L909), [config.c](https://github.com/git-for-windows/git/blob/v2.36.1.windows.1/config.c#L2041-L2122), [exec-cmd.c](https://github.com/git-for-windows/git/blob/v2.36.1.windows.1/exec-cmd.c#L24-L60), [path.c](https://github.com/git-for-windows/git/blob/v2.36.1.windows.1/path.c#L1560-L1585), [run-command.c](https://github.com/git-for-windows/git/blob/v2.36.1.windows.1/run-command.c#L264-L280), [compat/mingw.c](https://github.com/git-for-windows/git/blob/v2.36.1.windows.1/compat/mingw.c#L3307-L3355). These establish source-level runtime prefix and config/attribute behavior, not all compiled constants or launcher/module effects.

## Specific decision requested from independent reviewer

1. Can an independently reviewed, source-bound allowlist of exact upstream release image hashes plus empirically demonstrated relative compiled roots be accepted as a narrowly scoped selected-writer profile? Bind the actual native writer and launcher chain to admitted program identity; an outer shim hash alone cannot identify its real writer. Unknown/mismatched binary, layout, environment, loader/module dependency or source completeness means Unsupported, not a guessed root.
2. Once separately accepted, name the exact system/global config and attribute sources lexically from that profile and frozen invocation. Existing metadata resolution and fresh exact Path Read frontiers then capture files, ancestor/link identities and missing-state witnesses. Revalidate all before mutation. No generic filesystem Read, scans, hidden child, broadened Git environment or implicit retry. Keep supported approved Git CLI and selected native final writer.
3. For target-tree attributes use already admitted tree/objects and exact source order, including external/info attributes, macros and absence. Keep ordinary and cached check-attr where supported; never equate cached with target commit. Reuse the #928 primitives without granting new authority.
4. Push shell is a separate effect: Windows Git uses sh and startup PATH changes. Hashing usr/bin/sh.exe alone cannot establish actual shell resolution. Retain the approved native query when supported and fail closed until selected child provenance is reviewed.
5. Develop Checkout/Commit first; no whole-issue completion until the six replacements and original Windows acceptance are satisfied.
