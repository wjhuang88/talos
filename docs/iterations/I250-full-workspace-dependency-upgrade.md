### Scope

- Re-run I248 audit from implementation-time `main` and use its provenance as the candidate source.
- Process all 56 distinct package names / 67 dependency identity rows, including patch/minor, major, pre-1.0, prerelease and multi-resolution cases.
- Upgrade to latest stable by default, including major releases; isolate candidates whose API, runtime, persistence, permission, sandbox, native or platform surface requires it.
- For any candidate that cannot safely land, record `Blocked` or `Exception` with owner, concrete reason, revisit trigger, validation gap and rollback plan; do not silently retain an old version.
- Preserve default feature combinations, workspace membership, public API compatibility contracts unless a migration is explicitly accepted, and existing `cargo run`/`cargo build` behavior.
- Advance `DEPENDENCY-BASELINE` only after implementation evidence is merged and verified.

### Non-Goals

- No unrelated refactors or product behavior changes.
- No automatic `cargo update` acceptance without candidate attribution and validation.
- No release/tag/publication, workspace dependency centralization, or new helper runtime unless separately selected and governed.

### Acceptance

- Every identity in the fresh audit has a final disposition: upgraded to latest stable, current with evidence, or blocked/exception with complete ownership and revisit data.
- Manifest and lockfile changes are attributable to listed candidates; no unexplained transitive churn remains.
- Generic locked validation, affected-domain tests, feature matrix and platform checks pass for each landed batch.
- Public/API, runtime, persistence, permission/sandbox, native and provider impacts receive the domain-specific review required by `DEPENDENCY-UPGRADE.md`.
- Existing default Cargo behavior is regression-checked before and after the upgrade.
- Accepted baseline advancement cites an already-merged implementation commit and does not self-certify.

### Planned Validation

- `bash scripts/dependency_audit.sh --live --baseline docs/reference/dependency-baseline.json --format json` with recorded source SHA/timestamp.
- Full locked format/check/clippy/test and release preflight after local convergence.
- Candidate-specific tests for `rmcp`, `wasmtime`, `gix`, TUI/rendering, network, storage, parser/native and permission/security surfaces as actually affected.
- Both governance validators with explicit `COLLABORATION_VALIDATION_BASE=origin/main`, `git diff --check`, secret/generated-artifact scan and staged-diff inventory.
- Exact-head CI and independent authorization-specific review only for the stable candidate stage, not for each local edit.

### Documentation To Update

- I250 owner, `DEPENDENCY-002`, `DEPENDENCY-UPGRADE.md` only where generic gaps are found, accepted baseline, Issue #474 and derived Board/index/manifest views.
- Per-candidate migration/exception notes and a final disposition table.

### Risks And Rollback

- Risk: API or runtime incompatibility, feature/default-scope drift, platform failure, native panic, or lockfile churn obscures attribution.
- Rollback: revert the complete candidate batch or isolated slice, retain the prior accepted baseline, and record the failed validation and follow-up owner. Never force-push or move a failed tag.
