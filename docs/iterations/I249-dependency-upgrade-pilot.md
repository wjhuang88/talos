### Scope

- Select exactly one direct external dependency from I248's live report.
- Update the minimum manifests/lockfile required by that candidate.
- Run generic locked validation and dependency/domain-specific checks.
- Record rollback, compatibility result, merged implementation evidence and baseline advancement.

### Non-Goals

- No batch upgrades, workspace dependency centralization, unrelated refactors, or release/tag/publication work.
- Do not choose a candidate from the Issue's historical 2026-09-02 table without a fresh audit.

### Acceptance

- Given a fresh I248 report, when one candidate is selected, then its exact name, old/new manifest and resolved versions, risk classification, and source SHA are recorded before editing.
- Given the upgrade, when locked checks and domain validation pass, then the implementation merges and the accepted baseline advances only in a later owner-first closeout.
- Given a failed validation, then the dependency change is reverted or remains explicitly blocked with an owner; no partial lockfile state is accepted.

### Planned Validation

- I248 Bash/PowerShell reports and exact candidate provenance.
- `cargo fmt --all -- --check`, locked workspace check/clippy/test, dependency-specific matrix, governance validators and `git diff --check`.

### Documentation To Update

- Accepted baseline, dependency-specific migration notes, I249 owner, backlog/Board and Issue #474.

### Risks And Rollback

- Risk: selected upgrade breaks API, runtime, persistence, permission or platform behavior.
- Rollback: revert the candidate commit and retain the previous accepted baseline; do not force-push or rewrite the tag.
