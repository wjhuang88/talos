## Objective

Publish `v0.7.0` as a minor release after `v0.6.1`, carrying the accepted I169 Transactional
Batched Steering Turn (TUI-044 / ADR-056) and its durable structured queue, receipt-based
ownership transfer, generation-safe lifecycle, Actor arbitration, exact request-plan boundary,
and transcript-first finalization on `main`.

## Release Boundary

- Includes commits reachable from `main` at the re-pushed tag commit.
- Includes synchronized workspace/internal dependency versions and EN/zh-CN release surfaces.
- Includes five platform archives plus SHA-256 checksums (pending workflow completion).
- Excludes crates.io publication, stable 1.0 SDK guarantees, and any REL-002 readiness claim.

## Validation And Publication

- `./scripts/release_preflight.sh v0.7.0` passed on macOS with Rust 1.97.0. The workspace test
  suite was run with `RUST_TEST_THREADS=1` to avoid a known pre-existing flaky test
  (`provider_discovery::tests::discover_network_error_is_bounded`) whose 2-second timeout is
  insufficient under high parallel-test contention; the test passes in isolation.
- Governance validation and `git diff --check` passed before the release commit.
- **Initial tag push** at `95351f64` failed CI preflight: the closeout task included in the
  release commit had `**Status**: In progress` which triggered the collaboration-claim
  validator's active-owner check. The closeout task lacked a `## Collaboration Claim` section,
  causing `validate_collaboration_claims.sh` to fail. Local preflight had passed because the
  file was untracked at preflight time and `git diff` did not include it.
- **Fix**: the closeout task status was corrected to a non-active value and the tag was
  re-pushed to point to the corrected commit. Future releases should follow the v0.6.1 pattern
  (closeout task created after the tag, not in the release commit) to avoid this gap.
- The tag-driven GitHub Release workflow was re-triggered after the tag re-push.
