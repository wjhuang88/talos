## Why the boundaries differ

A single Session/Agent authority does **not** mean there is already one shared host-construction API:
- CLI/TUI reconstructs an `AppServerSession` in a CLI-owned builder.
- Desktop and external SDKs construct `RuntimeBuilder`; its current durable-session API takes `DurableSession`.
- Domain stores contain the production SQL/file implementation and business invariants. Moving their constructors without changing observed behavior is not synonymous with replacing those domain contracts.

E0 records these differences before any E2/E3 change. The production default is unchanged.

## Compile-time dependency truth

```text
CLI/TUI / Desktop / embedded SDK -> talos-runtime -> talos-session -> rusqlite (bundled SQLite)
CLI local domain callers ----------> talos-memory/evolution/exploration -> rusqlite
```

This is a *logical* dependency illustration; no complete Cargo feature-closure proof was executed. It does not establish that all product profiles use every crate, and injection of a trait would not make the binary SQLite-free.
